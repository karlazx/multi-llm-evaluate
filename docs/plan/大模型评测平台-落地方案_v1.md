# 大模型评测平台 — 完整落地方案 v1

> 版本：v1（2026-08-16）｜状态：待老板确认后交 Claude 落地
> 定位：一个"用例驱动 + 多协议 API 跑测 + 三级评估（自动判分/AI裁判/人工盲评）+ 报告导出"的私有模型选型平台，未来沉淀为小红书内容数据资产。

---

## 0. 决策摘要（TL;DR）

**结论：不造轮子，基于 promptfoo（MIT）做轻量二次开发，自建"用例库 + 人工盲评页 + 报告导出"三层薄壳。**

- 市面上同类开源产品充分（promptfoo / DeepEval / OpenCompass / EvalScope / Langfuse / Opik 等 15 个已盘点），但**没有任何一款 100% 覆盖六项需求**。
- 你需求里约 70% 的隐性工作量（协议适配 / 并发调度 / 裁判模板 / 成本统计）开源引擎已解决，二开薄壳单人数周可达 MVP，自研只适合强差异化场景——你目前不属此类。
- 引擎选 promptfoo 的核心理由：**原生支持 OpenAI v1/v2 + Anthropic 双协议**（正好命中你的接入要求），llm-rubric/g-eval 裁判可配置任意模型，逐格 token/延迟/美元成本统计，MIT 许可可自由改。
- 需对冲的风险：promptfoo 2026-03 被 OpenAI 收购，架构上保留引擎可替换性（EvalScope 为同构备胎）。

## 2. 技术选型

### 2.1 引擎：promptfoo

| 决策点 | 选择 | 理由 |
|---|---|---|
| 跑测引擎 | promptfoo（MIT） | OpenAI v1/v2 + Anthropic 双协议原生支持、可配任意 OpenAI 兼容端点 |
| AI 裁判 | promptfoo 的 llm-rubric / g-eval 断言 | 裁判模型可配置为任意 provider，结构化评分细则 |
| 成本统计 | promptfoo 结果 JSON 逐格 token/延迟/$ | 直接复用，报告层再聚合 |
| 备胎引擎 | EvalScope（Apache-2.0） | 同为"API跑测+裁判+竞技场"形态，应对上游收购风险 |

### 2.2 总体架构

```
┌─────────────────────────────────────────────────┐
│  薄壳层（自研，本次开发主体）                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐ │
│  │ 用例库    │ │ 盲评页    │ │ 报告层           │ │
│  │ SQLite   │ │ 匿名双栏  │ │ 排行/分维度/穿透  │ │
│  │ +版本快照 │ │ +ELO     │ │ +成本看板+导出    │ │
│  └──────────┘ └──────────┘ └──────────────────┘ │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐ │
│  │ 产物预览  │ │ 自动判分器│ │ 小红书导出       │ │
│  │ HTML渲染 │ │ 规则脚本  │ │ 卡片素材生成     │ │
│  └──────────┘ └──────────┘ └──────────────────┘ │
└─────────────────────────────────────────────────┘
                        │ 调用
┌─────────────────────────────────────────────────┐
│  引擎层（promptfoo，复用）                        │
│  协议适配 / 并发调度 / 裁判模板 / 成本统计         │
└─────────────────────────────────────────────────┘
                        │ API
┌─────────────────────────────────────────────────┐
│  模型层：OpenAI v1/v2 · Anthropic · 兼容端点     │
└─────────────────────────────────────────────────┘
```

### 2.3 技术栈

- **后端**：Python（FastAPI）— 与 promptfoo 结果 JSON 解析、脚本判分器、报告生成天然契合；Claude 开发效率高。
- **前端**：React（Vite）单页应用，管理台形态。
- **存储**：SQLite（单用户够用，零运维）→ 用例、模型配置、评测轮次、盲评投票；产物快照存本地目录。
- **引擎调用**：promptfoo 以 CLI/Node 库形式被后端封装调用，输入为生成的 promptfooconfig YAML，输出为结果 JSON。
- **部署**：Docker Compose 单机，本地或轻量 VPS 均可。

## 3. 核心设计

### 3.1 三级评估体系（本方案核心）

| 层级 | 适用用例 | 机制 | 可信度 |
|---|---|---|---|
| L1 自动判分 | 有确定性答案/规则可校验的题（1/2/3） | 脚本规则（Python/JS）判对错/打分，promptfoo assertions 承载 | 最高，客观 |
| L2 AI 裁判 | 开放式主观题（4/5/6） | llm-rubric 结构化评分细则，可配置裁判模型，位置交换消偏 | 中高，需校准 |
| L3 人工盲评 | 全部/抽样 | 匿名双栏盲评，ELO 排名，与 AI 分数并列展示 | 最高，但重 |

- **默认模式**：L1 全量 + L2 全量 + L3 抽样 5–10% 校准。
- **全量人工模式**：用户可切换为所有题都人工盲评。

### 3.2 用例模型

```
Case {
  id, title, prompt(输入), 
  dimension: 代码|写作|推理|长文本|工具调用|多模态|其他,
  type: objective(客观题) | subjective(主观题) | code(代码题),
  expected_answer / rubric(评分细则) / assertion_script(判分脚本),
  source: self(自建) | public(公开),
  tags, status(active|archived), version
}
```

- 支持批量导入（JSON/CSV），存量 evaluate_case.md 6 题先手工录入。
- 用例集（CaseSet）按业务场景分组；版本化用快照（git 或带版本号归档）。

### 3.3 模型接入

- 接入方式统一：填 endpoint / api_key / model 名 / 协议类型（openai-v1 | openai-v2 | anthropic）/ 默认参数。
- key 加密存储，界面脱敏显示；一键"测试连接"。
- 裁判模型与评估模型走同一接入表，仅用途字段区分。

### 3.4 产物预览（代码类用例专用）

- 模型输出的 HTML/JS 代码，提供 iframe 沙箱渲染，人工/AI 评估时可直接看效果。
- 这是题 4/5/6 的刚需，也是小红书可视化素材的来源。

## 5. 迭代规划（分阶段 + 验收标准）

> 每阶段独立可验收，验收通过才进入下一阶段。交付物存项目文件目录 `/model-eval-platform/`。

### M0：技术验证（≈2-3 天）
- **目标**：验证 promptfoo 原生跑通"你的业务用例 × 多模型 × AI 裁判"闭环。
- **交付物**：一个 promptfooconfig.yaml + 结果 JSON，跑通 3 个用例（题2/3/4）× 2-3 个模型。
- **验收标准**：
  - [ ] OpenAI v1、v2、Anthropic 三种协议各至少跑通一个模型
  - [ ] llm-rubric 裁判能输出结构化评分
  - [ ] 结果 JSON 能读出 token/延迟/成本字段
  - [ ] 题2/3 的确定性答案能被 assertions 判对错

### M1：用例库 + 模型接入 + 跑测引擎（≈1 周）
- **目标**：后端骨架 + 用例管理 + 模型接入 + 跑测编排。
- **交付物**：可运行的 FastAPI 服务 + React 管理台（用例 CRUD、模型配置、发起评测）。
- **验收标准**：
  - [ ] 6 个存量用例可录入并分类（objective/subjective/code）
  - [ ] 模型接入支持三种协议，连接测试通过
  - [ ] 发起评测后并发跑测，单用例失败不影响整体
  - [ ] 原始产出物全量落盘可追溯

### M2：自动判分 + AI 裁判 + 报告（≈1 周）
- **目标**：三级评估里的 L1+L2 落地，产出首个端到端评测报告。
- **交付物**：判分脚本执行 + 裁判配置 + 报告页（排行/分维度/穿透/成本看板）。
- **验收标准**：
  - [ ] 题1/2/3 自动判分结果正确
  - [ ] 题4/5/6 走 AI 裁判，评分附理由
  - [ ] 报告页显示总分排行 + 分维度得分 + 单用例穿透 + token/费用/耗时
  - [ ] 报告按轮次归档，不覆盖历史

### M3：人工盲评 + 产物预览（≈1 周）
- **目标**：L3 落地，代码类用例可预览。
- **交付物**：盲评投票页 + iframe 产物预览 + 校准面板。
- **验收标准**：
  - [ ] 盲评匿名双栏，模型名隐藏，投票结果回写
  - [ ] 题4/5/6 产出 HTML 可沙箱渲染
  - [ ] AI 分与人工分一致性可查看
  - [ ] 支持"抽样校准"与"全量人工"两种模式切换

### M4：打磨 + 导出 + 上线（≈1 周）
- **目标**：报告导出、增量评测、部署文档，v1 定版。
- **交付物**：Markdown/PDF 导出 + 增量评测 + Docker 部署说明 + 使用文档。
- **验收标准**：
  - [ ] 报告可导出 Markdown/PDF
  - [ ] 新模型增量评测并入历史对比
  - [ ] Docker Compose 一键起服务
  - [ ] 使用文档完整（含如何录用例、接模型、读报告）

## 6. 整体验收标准（v1 定版）

1. 端到端闭环：录用例 → 接模型 → 跑测 → 三级评估 → 出报告，全程可用。
2. 三种协议（OpenAI v1/v2、Anthropic）均能真实跑通。
3. 报告含：总分排行、分维度得分、单用例穿透、token 用量/费用/耗时。
4. 三级评估体系可用：自动判分正确、AI 裁判可配置、人工盲评可校准。
5. 代码类用例产出可预览。
6. 历史报告可追溯，新模型增量评测不覆盖旧结论。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| promptfoo 上游收购后中立性变化 | 架构保留引擎可替换，EvalScope 为同构备胎；薄壳与引擎解耦 |
| AI 裁判偏差（偏长回答/位置偏差） | 结构化 rubric + pairwise 位置交换双跑 + 抽样人工校准 |
| 用例数据污染 | 以自建业务题为绝对主体，公开题仅作辅助参考 |
| 模型版本漂移 | 报告锁定"模型+版本+日期"三元组 |
| 成本失控 | 跑测前预估 token 成本，报告页持续展示费用，后续可加阈值告警 |
