## 三、关键实现核对

**L1 判分器接线（转 M2 的第 2 个点）**：
- `judge.ts` 新增 `l1JudgeByName(name)`，按 `case.assertion_script` 名称返回对应判分器函数，替代原 `judgeForCase` 空壳。
- 三个判分器 `judgeSentence`/`judge24Point`/`judgePasswordLock` 均已实现且 mathjs 安全求值（禁原生 eval）。

**max_tokens 按用例 type 调（转 M2 的第 1 个点）**：
- `evalRunner.ts` `maxTokensFor(type)`：code → 16384，其它 → 4096；`buildProvider` 接收 `opts.maxTokens` 覆盖硬编码 8192。

**L2 AI 裁判**：
- `resolveJudgeModel`：优先 `run.judge_model_id`，否则取 `is_judge=true AND status='active'` 首个模型。
- `needJudge` 校验：存在主观/代码题但无裁判模型 → 提前 `failed` 并抛错（不静默跑空）。
- `buildAssertions` 对 rubric 题传 `provider: judgeProvider`（裁判模型可配）。

**跑测引擎重构**：由「模型级并发」改为「用例级并发」——每个用例一次 `evaluate()`（所有模型一起跑），因 `defaultTest.assert` 是 evaluate 级统一，按用例拆分才能让不同题挂不同断言（L1/L2）。失败隔离保留（单用例 catch 后为每个模型记 error 输出）。

**判分入库**：`res.gradingResult.componentResults[0]` 取 score/reason，写 `judge_scores`；快照 `snapshot_json` 新增 `grading` 字段保留完整判分结果。

## 四、判分器算法复验

- **24点**：暴力枚举（含乘方/根号）确认 `3,4,9,10` 唯一初等解 `(10-4)^3/9 = 216/9 = 24`；`judge24Point` 经 `normalizeMath` 后 `math.evaluate` 得 24，`expr.match(/\d+/g)` 提取 [3,4,9,10] 各一次 → 判 pass，逻辑成立。
- **密码锁**：唯一解 12753，`countClue` 对 5 条线索全吻合（M0 已复验，本轮不重复）。
- **造句**：10 句 / 结尾一到十 / 倒数第二字不重复且不含第/是/为，规则清晰。
